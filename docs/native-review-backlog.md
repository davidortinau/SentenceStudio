## Vocabulary Quiz autoplay and launch (review of `48c97189..4e1921a9`, 2026-11-06)

- **9. Off-main-thread work and Android parity of Back while loading.** `src/SentenceStudio.Native.iOS/App/ApplicationController.Quiz.cs:612` (StartQuizAsync), `src/SentenceStudio.Native.Android/AndroidSliceShell.cs:356`. Moving database work off the main thread at one call site was the wrong altitude. That Task.Run is reverted: iOS has a UIKitSynchronizationContext, and the presenter is not thread-safe. If quiz database work must leave the UI thread, do it in the presenter or data layer for every command (Open, Retry, Resume, Start fresh, Next). Android also has no queued Back while the quiz loads; decide whether it should match iOS.
- **10. Autoplay request workflow copied in both heads.** `src/SentenceStudio.Native.Android/AndroidSliceShell.Quiz.cs:74` and `src/SentenceStudio.Native.iOS/App/ApplicationController.Quiz.cs:292`. Prompt-shown dedupe, one request per turn, the linked token and its compare-and-clear are repeated in both heads (AGENTS.md: no platform copies of workflows). A presenter-owned `PromptShown(turnId)` that keeps the request's cancellation would remove both copies.
- **11. Android timing logs bypass ILogger.** `src/SentenceStudio.Native.Android/AndroidSliceShell.cs:360` and `src/SentenceStudio.Native.Android/AndroidSliceShell.Quiz.cs:81` use `Android.Util.Log.Info` instead of the head's `ILogger` pipeline (AndroidServiceHost), so the "quiz opening" and "prompt on screen" lines skip the logging configuration the presenter's "autoplay started/finished" lines go through.
- **13. Effect keys from identity hashes are not unique.** `src/SentenceStudio.Native.Android/AndroidEffectKey.cs:32`. `RuntimeHelpers.GetHashCode` can repeat for two live instances, so "a new instance restarts the effect" is not guaranteed (a photo render report or viewer focus could be skipped). A per-instance sequence number or reference tracking would be exact.
- **14. Effect keys allocate on every quiz recomposition.** `src/SentenceStudio.Native.Android/AndroidSliceShell.Quiz.Compose.cs:34,50`. `AndroidEffectKey.Of` runs twice per recomposition (each keystroke in the answer field): a params array, a boxed bool, escaped strings and a join, even when the key is unchanged. Typed overloads or a cached key would avoid it.

## Vocabulary word ownership (one runtime rule, `b88a4dd4`, 2026-11-06)

- `src/SentenceStudio.Api/Coach/Operations/Handlers/CoachVocabularyHandlers.cs` (remove-word): a word recorded to no one is only unlinked from the learner's resources, so the row stays with no link and no owner. Decide whether such orphan rows should go (they hold nothing of the learner's once unlinked, but may hold someone else's memory aid).
- `src/SentenceStudio.Shared/Data/VocabularyWordOwnership.cs` (`StampAsync`, startup backfill and save/upload stamping): on the server, a save that adds a link or progress to an ownerless word records its owner when links and progress name one profile. The 2026-11-06 web journey saw it: a test word recorded to no one that only testsailor linked was recorded to testsailor by the progress row the dashboard created at sign-in, before the editor opened, so it was editable. This is recording, not runtime inference, and in production every such word was already recorded at startup (2026-11-05), but it means "read-only until the backfill" holds only until the learner's next save touches the word. It also counts links and progress only, while `scripts/assign-vocabulary-word-owners.sql` uses the delete rule's full "uses" (also sentences, minimal pairs and answers, phrases), so a word another learner's sentence or pair uses can be recorded to the one learner who links it. Decide whether saves should record owners of existing words at all, and if so align `StampAsync` with the script.
- `src/SentenceStudio.Shared/Data/VocabularyWordOwnership.cs` (`AvailableTo`): a learner may still see, link and reuse an ownerless word that only they use (by link or progress), and linking it records them on the server. That is reuse, not permission to change it, but it is the last runtime path that reads links to decide something about an ownerless word.
- `src/SentenceStudio.Shared/Migrations/20261104162953_AddSyncDeletionLog.cs` (`sync_deletion_by_word`): the deletion log still names a deleted ownerless word's owner from its links and progress, to choose which devices receive the delete. It decides delivery, not permission; a later migration could make it recorded-only.
- `src/SentenceStudio.Api/Sync/NativeSyncStoreBindings.cs:148`: the check that a store's earlier headerless history names only this owner now sees fewer owners (words are no longer inferred); the other tables still name them.
- `src/SentenceStudio.Shared/Data/LearningResourceRepository.cs:1285` (`GetResourcesForVocabularyWordAsync`, used by the web/MAUI word editor): lists every resource that links the word, other learners' included; it should list only the learner's.
- `src/SentenceStudio.UI/Pages/ResourceEdit.razor:1013` and `src/SentenceStudio.UI/Pages/Index.razor:843` (`SaveWordAsync`): fill a blank lemma or language on an existing word without asking whose it is, so they can write to a word recorded to no one.
- Production data (2026-11-05 dump): 213 ownerless words are linked only from 2 resources that have no owner, 28 only by a deleted account's progress, and 96 by two or more learners (5 of them with a memory aid). They stay read-only for everyone; deciding whose the 2 resources are (the Captain's call, like the audio rows) would let the backfill record the 213.
- Devices: until its first sync after the deploy, a device's legacy words have no recorded owner locally and open read-only there; old MAUI builds can still edit them offline, and the server refuses those edits (as it did before for words with no single owner).
